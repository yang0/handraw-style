# 画幅、分镜与素材契约

适用于所有模态的新制作、横竖屏改版与跨画幅交付。以下白板配置是当前可运行接口；其他模态或期内脚本按同一原则适配，但不假设它们已经消费全部字段。

## 1. 画幅从输入一路传到编码

先确定目标画幅与交付端。用户已给比例/尺寸则直接采用；没有给时沿用明确的项目默认并告知。不能把某期9:16当作全项目要求。

| 目标 | 常见1080P尺寸 | 推荐重排起点 |
| --- | --- | --- |
| 16:9横屏 | 1920×1080 | 标题顶部；主体左右分栏；步骤横向；对比左右；有画内字幕时另留区域 |
| 9:16竖屏 | 1080×1920 | 标题顶部；主体上下组织；步骤纵向；对比可上下；有画内字幕时避开主视觉 |
| 自定义比例 | 用户给定偶数尺寸 | 根据内容密度重新分配标题、图像、说明和字幕区域 |

把width、height、fps、aspect_ratio、orientation写入episode.json。Canvas像素、CSS显示、浏览器viewport、离屏缓冲、截图与编码均采用该尺寸；导出前检查一致性。变更FFmpeg尺寸、拉伸整幅画面、给竖屏加黑边不等于横屏设计。源图以contain保持完整；需要cover裁切时指定焦点并检查人物/关键物不被裁掉。

位置用归一化区域或随尺寸计算的布局配置；标题/字号/线宽跟短边或独立画幅档位走。横竖屏应有各自的区域分配，不只等比缩放坐标。字幕预留随画幅和平台UI调整，不固定“底部240px”适用于所有分辨率。默认白板横屏是分栏/横向流程，竖屏是上下/纵向流程；内容放不下时报错并拆幕，不截掉步骤。

字幕是否存在由subtitle_mode决定，见[字幕与信息手册](subtitle_and_information_guide.md)。无画内字幕无需强制字幕条或默认额外堆字。默认白板仅关闭字幕层，不自动改变主视觉布局；新设计可另行调整留白。横竖版本可采用不同字幕策略，但不静默改变已经确认的选择。

双版本一般复用剧本、配音、真实字幕时间和插画源图，各自建立画面配置与QA；只有用户要求改变节奏/内容才重做声音。保留各版输出，例如outputs/landscape/与outputs/portrait/，旧成片不覆盖。封面比例独立于视频比例，分别构图。

## 2. 可实现的素材与风格

读取当前项目风格、图型、配色的权威记录后再选ID；注册风格不等于现成透明贴纸，图型文字规则不等于可执行SVG布局。按模型能力决定风格名称、正向特征与参考图是否需要发送。记录实际使用方式，勿宣称默认CLI自动解析全库。

给每幕指定visual_role（人物场景/物体隐喻/流程/对比/数据/金句等）及真实素材路径。具体人物、产品和场景需可见的实际图片；纯逻辑关系可用明确的矢量图表。纯文字金句页可以作为有意的节奏选择，但不能以一串装饰框冒充全片插画。用户要求图像时，渲染前核对主视觉已生成/导入且实际被使用。

- 图集与独立PNG均可；图集列行数随内容选择，不固定3×2、六格或同一角色。
- 每张图集有明确source_rect、格子语义、身份一致性与透明留边；采样框不越界、不串格。保持宽高比，不把一张完整图集当单张贴纸。
- 声称透明时检查真实alpha并在浅/深底上复核；PNG扩展名、提示词里的transparent或棋盘格不证明透明。
- 记录素材来源、文件哈希、实际生成提示词及参考图使用；项目案例产生的插画标明“本期生成”，不是库中已有文件。
- 图片/字体失败应中止或明确征得降级选择，不能默默输出空画面。

### 2.1 角色与场景共同设计

适用于有角色表演、道具接触或环境响应的镜头；纯景观、图表和有意的静态姿态不强制补角色。先写互动事件，再一起确定场景、角色和动作素材；不要先分别生图，合成时才发现没有站立面、接触物或足够动作空间。叙事长卷的分镜表与示例见[长卷手册](unbounded_scroll_director_guide.md)。

| 适配项 | 制作时明确的内容 | 合成时检查 |
| --- | --- | --- |
| 画风与光照 | 共同色板、线条/笔触、轮廓、材质、主光方向与软硬；跨画风时写各段变化 | 角色不显得另贴一层，明暗、投影和环境色相符 |
| 比例与透视 | 人物身高相对桥、门、方块等对象的尺度，视角、朝向、站立面及活动范围 | 人物与物件同处一个空间，动作不穿地面或超出可用范围 |
| 脚底与移动 | 每帧脚底锚点、地面/桥面路径、接地/离地状态及角色移动方向 | 接地时脚底贴合站立面；腾空与落地有过程；跨段高度和步态相位连续 |
| 手部与道具 | 持握的手、手部锚点、释放/接触点、道具尺寸与持有状态 | 不换手、不漂移、不重复出现；道具从接触位置开始运动 |
| 目标与路径 | 被交互对象、目标接触点、运动路径、释放/碰撞/落地时刻 | 碰撞发生在可见目标上，环境响应由接触事件触发 |
| 前后遮挡 | 背景、角色、道具、桥栏/树枝等前景和响应特效的绘制顺序或遮罩 | 人物经过栏杆等遮挡物时顺序正确，手与道具按动作需要显露 |

坐标标明所属空间（源图像素、角色局部坐标或场景世界坐标）及缩放变换；接触点随角色和相机变换，不独立写成固定屏幕坐标。素材清单记录实际姿态/帧对应的锚点、尺寸和透明范围，不能只列“背景一张、人物一张”。不可独立运动的关键物若已画进背景，应准备可分离素材或明确的遮罩方案，避免原物和动态副本同时出现。

跨画风保持同一身份参考、主要识别特征、持有物和动作阶段连续；材质、描绘方式及必要造型随世界适配。先对照边界两侧的同一动作，再检查合成过渡；不把换画风处理成换人、换手或瞬间重置姿态。帧数、图集网格和站立高度按动作选择，不照搬参考工程的固定8帧或像素数。

静态姿态、动作关键帧与连续动画的选择及所需实现见[长卷手册的表现层级](unbounded_scroll_director_guide.md#13-表现层级与素材需求)。这些是设计与验收要求，不是当前白板JSON或长卷CLI自动消费的新字段。

### 2.2 知识长卷的解释素材与坐标

用连续画卷解释知识时读取[知识长卷指南](scroll_knowledge_guide.md)。每个知识点指定可见对象/状态、过程或关系、实际素材路径与事实来源；程序化图形记录其数据和含义。写明示意比例、时间压缩和必要简化；概念配色跨段一致，不能因换画风而把同色改成另一个概念。

对象、箭头和路径通常用世界坐标；对象标签随世界锚点投影到屏幕，按实际字体测量并避让；章节导航和解说字幕可以用屏幕坐标。记录锚点、图层顺序、出现/结束区间、保持状态及相机焦点。推近时保持文字可读且不裁关键对象，标签不随背景缩到无法阅读；无可执行的避让实现时由分镜明确摆位并抽帧核对，不宣称自动排版已实现。

需要运动的过程对象应独立成层或具备可执行的绘制/遮罩方案；生成背景里的文字不作为精确标签来源，术语、单位与来源在可编辑层排版。隐喻与真实过程分别说明，示意路径不可冒充真实物理轨迹。与角色接触的对象还须满足第2.1节。

这些为知识长卷的设计记录与验收契约，不是当前白板JSON或长卷CLI已经支持的新字段；首次接入时验证加载、事件、标签和相机，再登记能力状态。

## 3. 当前白板接口

`hvp new --mode whiteboard`创建的是草稿：填写script.txt、style_code与palette，并按实际配音语义段编写storyboard.json。初稿可先按预期段落设计；配音后核对服务实际分段，用segment_indices合并连续片段。每个实际语音段按顺序覆盖一次，不能遗漏或重复。

```json
{
  "version": 1,
  "scenes": [
    {
      "id": "question",
      "segment_indices": [0, 1],
      "layout": "hero",
      "layout_code": "按当前库选择并核对",
      "title": "本期问题",
      "body": "一句辅助说明",
      "image": {"path": "assets/main.png", "transparent": true},
      "takeaway": "可选的一句结论"
    },
    {
      "id": "actions",
      "segment_indices": [2],
      "layout": "steps",
      "title": "行动建议",
      "items": [
        {"text": "第一件事", "image": {"path": "assets/atlas.png", "source_rect": [0, 0, 512, 512]}},
        {"text": "第二件事", "image": {"path": "assets/atlas.png", "source_rect": [512, 0, 512, 512]}}
      ]
    }
  ]
}
```

接口的layout值：hero为图文主视觉；steps为1–4项一图一句；compare为恰好两个完整主视觉（items结构同steps）；diagram为2–4个nodes字符串组成的方向图。上限只是默认模板容量，更多内容拆幕或用期内布局，不限制题材。`layout_code`用于来源记录，设计者需按权威规则检查；它不会自动改变layout实现。palette是实际CSS十六进制色，不直接传C-*编号。

当前默认只消费work/timing.json的duration和segments；duration应是实际音频文件实长，每段需要text/start/end，可选caption_lines显式断行。其他TTS/ASR的时间线由期内适配器映射，不改造外部工具来迁就模板。build前验证草稿与素材；已有期内produce.py仍优先委托，不擅自替换其CLI协议。

episode.json可设subtitle_mode为burn-in/sidecar/none，默认白板及通用mix已消费；缺少时沿用burn-in。cues和segments仍作为内部语音数据保留，不能以空数组关闭字幕，避免破坏分镜覆盖。仅burn-in验证caption_lines并绘制字幕；sidecar用原text及真实起止生成SRT；none不创建活动字幕交付或旧SRT链接。其他模板/期内脚本先核对实现，不假设已消费字段。

画内字幕以语义短句断行：优先标点、词组，避免“手机放 / 远”；不按等字数虚构词级时间。显式caption_lines适合术语、短诗与固定读法，其完整内容应与原text一致。每屏文字测量实际字体宽度；若必须缩到难读，缩稿或拆幕。视图切换不能改ASR原边界，阅读延长需避开下一句。

## 4. 检查矩阵

横屏与竖屏分别检查，而不是检查一个画幅后宣布两者都通过：

1. 每幕起、中、尾及实际讲话帧；图像完整、文字安全区、图型语义和视觉一致性。按模式检查：burn-in字幕不断错词且不遮挡；sidecar无画内字幕且SRT正确；none无解说字幕、活动字幕字段为空且画面信息完整。
2. 每个切点前后与中间状态；无非预期空白、闪白、重影、裁切跳变。
3. 同一时间先渲染、回跳、再渲染，结果一致；确定性随机/绝对时间驱动避免导出与预览不同。
4. 最终尺寸、帧率、帧数、音画时长、全片解码、编码后真峰值及响度；字幕/封面/试听/播放器链接真实存在且指向同一版。
5. 区分机器检查、视觉复核、实际观看/听审、用户接受。截图不证明动态节奏自然，ASR不证明配音听感自然。

默认实现自测：`python skills/handraw-video-producer/tests/test_whiteboard.py`；浏览器/编码离线烟测加`--browser`。自测复用本地已有图片或临时测试素材，不调用收费生成服务。测试输出不是新制作成片，也不更新原片预览。
