# 插画手绘白板导演手册

> 版本：v1.2。模式：sketch / whiteboard。主题与时长开放，支持横屏、竖屏；不把某期的画风、颜色、音色、幕数与尾卡时长变成固定模板。

目标是边讲边建立可理解的视觉关系。先做好图像与逻辑，再用手绘动作组织信息；只有框线与文字的样板不等于完成了插画知识视频。

## 1. 先定内容、全片视觉、全片运动

按受众与篇幅选一个能讲清的问题。知识内容保留来源，区分研究结论、通俗化解释和建议；高风险结论需核验权威来源，不能把科普写成疗效或收益承诺。

结构可以是问题→解释→建议，也可以是过程、对比、误区、因果或数据关系。幕数由内容与配音实长决定，不强制四幕、五幕或每段3–5秒。约30秒的单一问题常适合少量信息节点，但不要为凑时间堆字或固定加四秒静音。

先写全片视觉方案（风格、配色、人物/图像类型、图型关系、画幅），再写运动方案（揭示、连线、焦点、换页与阅读停留）。逐幕表包含编号、时间/时长、旁白要点、主视觉/素材、图型来源、具体动作和衔接。用户已授权自主制作可继续执行；需要串行确认的项目沿用其确认要求。

同时确定图文、配音与字幕的分工，读取[字幕与信息手册](subtitle_and_information_guide.md)。标题、步骤、图内标签负责核心关系，配音补充解释；画面已表达清楚时可不重复叠加全文旁白字幕。静音观看、无障碍或交付要求仍需相应字幕，不能把本期的无字幕选择固化到所有白板。

## 2. 深度结合当前手绘项目

读取当前风格库、图型库和配色，不照抄本手册的历史ID映射或数量。图型以项目skills/handdraw-style-prompter/references/layouts/中的对应ID文件为权威；按模型能力决定风格激活与参考图。资产与画幅契约详见[frame_and_asset_contract.md](frame_and_asset_contract.md)。

- 风格适合信息密度，不固定FA-012或特定作者。
- 流程、Before/After、对比、矩阵等结构按主题选择，在设计案说明如何落到画面。默认白板只实现hero/steps/compare/diagram四类；其他图型用期内模板，不能只写编号就宣称已接入。
- 颜色ID与最终色值分开记录，不把C-*当CSS色；文字、背景和强调层保证可读。
- 具体人物/物体/场景使用对应真实图像，逻辑节点可以是有意义的矢量关系图。选择独立图或图集均可，数量与格子形状不固定。未生成、未导入或未接入的素材不能算作已有插画。

## 3. 动效是信息动作，不是默认全角色动画

白板层可包含底色/轻纹理、双描边框线、逐段连线、关键词马克笔、文字显现、插画遮罩揭示。根据主题取舍，避免每页重复所有效果。

- 框线/箭头沿路径绘制，可用少量超尾、复线与笔尖；粗细随短边调整。
- 插画用带不规则边缘的遮罩擦出，时长随节奏选择，不固定0.4秒。保持源图比例与透明留边，完整显现后不留下裁切刷边。
- 字体淡入、遮罩擦写、真正矢量笔顺是三种能力。没有字形路径时称为遮罩擦写，不冒称汉字逐笔书写。
- 插画整体位移/缩放只是有限动效；只有可用分层/骨骼/姿态素材才设计更复杂的表演，不宣称贴纸微移是完整角色动画。
- 动画由绝对时间驱动；揭示与翻页分开设计，不重复闪白。有意硬切、一次页滑、叠化均可，按内容选择并检查切点。

## 4. 横竖屏不是同一页裁切

横屏常用左文右图、横向步骤与左右对比；竖屏常用上文下图、纵向步骤和上下对比。相同旁白与素材可以复用，主体位置、字号、步骤轴、字幕区域应各自计算。遵循共享[画幅与素材契约](frame_and_asset_contract.md)，不把1080×1920、底部240px或固定卡片坐标带到横屏。

放不下时减少当屏信息或拆幕；不得用break丢掉后续步骤、按逗号只取半句话，或把字缩到无法阅读。对比的两个主视觉应完整、可比较；流程每步短句与图像对应清楚。

## 5. 先有可追溯声音，再定最终画面

指定服务/音色优先执行可用链路，通用CLI默认仍是Edge，不把本次火山适配当作所有服务自动接入。指定配音与声画修改读取[跨模式声画指南](audio_transition_revision_guide.md)。

按语义与读法组织旁白，不逐逗号机械合成。实际服务参数、回执、可解码音频与真实文件实长是证据；HTTP成功、参数名字或演播文档不证明实际生效。分块音频按接口编码规则解码，不随意拼带padding的Base64文本。

用实际音频及服务时间戳/按需ASR建立语音与镜头锚点；显示或交付字幕时使用同一实际时间线，句级和词级精度分别说明。画内字幕优先标点和词组断行，固定句可显式caption_lines；不显示时不必处理未用的字幕排版，也不因去字幕重跑ASR。不用字幕首尾反推含静音的音频总长。配音缓存绑定文本、服务/模型/音色/演播/语速及音频哈希；ASR缓存绑定实际源音频，配置变化不按文件存在就复用。

气口、转场、结尾阅读单列预算。超出预算时先缩稿/调整演播或沟通时长；偏短可有意保留结论/视觉动作，不能机械补长静音。没有必要不对旁白全片拉伸变速。

## 6. 当前CLI与交付

```bash
python skills/handraw-video-producer/bin/hvp.py new "本期标题" --mode whiteboard --aspect 16:9
python skills/handraw-video-producer/bin/hvp.py new "另一标题" --mode whiteboard --aspect 9:16
python skills/handraw-video-producer/bin/hvp.py new "无字幕图文知识" --mode whiteboard --aspect 9:16 --subtitle-mode none
```

新建仅产生草稿。完成剧本、素材、storyboard.json与实际配音段映射后再tts/render/mix/covers；无素材或漏段落时报错。现有期内produce.py优先委托，子命令协议需实际检查。旧样板只有文字框，不能作为已验证插画能力范例。

交付视频、按需字幕、独立横竖封面、发布文案与检查记录；链接指向同版。字幕策略为burn-in/sidecar/none，默认模板已接入，旧工程未指定保留burn-in。none不交付SRT但保留内部时间线及图文；sidecar不烧录并提供SRT。横竖分别做起中尾/实际讲话帧/切点/回跳/解码检查，再实际观看与听审。没有用户确认时保持待审。
