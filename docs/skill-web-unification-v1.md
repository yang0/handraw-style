已知限制：没有新 `/api/v1` 时，涉及这些服务端依赖的命令会明确返回 403/404，不会误写本地“同步成功”。客户端对发布结果使用公开作品详情做无凭据回读；完整关联核验仍可能因字段/传播差异显示 `verified=false`，需结合真实环境验证。用户的本地生成历史不会因为执行 `record` 就被上传或公开。

源码使用方式：在**完整 handraw-style 仓库或 full ecosystem 包**执行 `python scripts/handraw_cloud.py --help`。现有仅含单个画风提示词的 standalone ZIP 不包含额外 `handraw-cloud` 子 Skill 及其依赖，不应把该发行版宣称为支持云空间。

离线回归工作流：`.github/workflows/skill-cloud-tests.yml`，覆盖设备授权、请求来源限制、图库版本、冲突/权限、历史私有文件、作品分享令牌兼容。联机真实验收必须由两个仓库完成。

## 产品目标

Handraw = 一个网站账号 + 一个个人创作空间 + Skill 和网站两种创作入口 + 一个作品和社区生态。

用户闭环：
1. 在 Skill 安全绑定已有 Handraw 网站账号。
2. 自建角色/道具/场景/参考图库，本地可使用，授权后私有同步云端。
3. 自建画风和图型，本地创建、编辑、预览，登录后私有同步网站。
4. 网站中获得完整访问权的画风/图型同步到 Skill，离线可用；仅收藏但未获取完整资格时只能浏览摘要。
5. 通过 Skill 创作图片，先保存在个人私有生成历史（用户可选择上传到私有云端）。
6. 用户主动确认发布时，才进入网站作品广场。
7. Skill 可查看作品的点赞、收藏、评论、回复和通知，数据与网站一致。

## 不可变更的关键规则

- **账号统一**：Skill 的当前身份对应网站同一 user_id，不单独创建“Skill 账号”。
- **默认私有**：本地图库、个人画风/图型、生成历史不能因绑定账号或同步操作而自动公开。
- **发布必须显式同意**：生成成功≠发布作品。Skill 草稿准备、打开预览不会上传或公开；只有用户明确授权后才能上传/发布。
- **收藏不等于解锁**：已收藏的画风/图型如未获完整内容访问权，不允许下载其完整定义。
- **尊重作者和版权**：继承作者、原始资源 ID、授权范围和版本；私人副本、收藏副本不能冒充原创。
- **官方资源只读**：不得修改、覆盖或重编号官方预置画风/图型及官方 IP 资产；用户资源独立存储。
- **画风与图型语义明确**：画风只提取媒体、质感、色彩、光影等视觉语言，不能吸收示意图人物、服饰、具体场景；图型描述布局规则。
- **离线优先**：断网时已合法缓存的资源正常可用；网络失败不能删除本地数据，未经用户同意不得替换冲突资产。
- **服务端权威**：授权、公开状态、云端 revision、作品与互动由网站服务端决定。
- **安全**：不把用户密码、网站 Cookie、访问令牌、用户私有图库、云端私有素材或生产密钥提交 Git。

## Skill 端功能拆分与目标体验

### A. 账号与授权（P0）

入口建议：绑定账号 / 当前账号 / 同步状态 / 解绑账号。

首次绑定：请求网站设备码 → 打开网站授权页 → 用户在网站登录并批准所请求的权限 → 设备兑换 scoped token → 校验网站账户 → 显示已连接用户名。

使用网站既有设备授权，不要求用户在 Skill 内直接输入网站密码，不手动复制浏览器 Cookie；令牌由系统安全凭据存储或经批准的安全存储方案保管。令牌被网站撤销时本地清除授权状态并提示重新绑定。

### B. 我的图库（P1）

现有 custom-asset-manager 的本地 library.json、WebP 图片与角色/道具/场景维护能力继续保留。Skill 增加本地 UUID、同步状态、服务器 revision、图片 SHA256、游标、删除状态；按需调用网站的个人图库 API。

支持：
- 本地创建/编辑/删除与离线查看。
- 用户开启后同步到本人私有云端；服务端不能记录本地绝对文件路径。
- 云端恢复到新设备，保留名称、标签、分类和稳定 ID。
- 同名素材不作为相同资产判据，避免误覆盖；图片冲突保留独立副本。
- 网络中断、409 版本冲突、服务端删除、限额与无权限有清晰提示和恢复操作。

### C. 我的画风与我的图型（P1）

创建 style / layout 结构化定义，支持中英文完整定义、版本、示例、作者、许可证、来源 ID、是否私有。云端同步采用独立于图片图库的资源 API，不把个人数据写入官方编号库文件。

画廊导航建议统一为：
- 官方画风/图型
- 我的画风/图型
- 我的收藏
- 我的图库

资源私有同步与主动发布为两个不同操作。所有本地 ID 和服务器 ID 映射须稳定；官方资源和用户自建资源不共享可冲突的展示编号。

### D. 我的收藏与授权完整内容（P1）

Skill 从网站拉取收藏、完整访问资格、资源版本。界面明确区分：
- 已收藏：记住资源入口。
- 已获取：账号有权获取完整定义。
- 已同步：定义已经下载到当前 Skill，可按许可离线使用。

未解锁资源不返回完整定义；免费可完整获取或合法解锁的资源才进入本地可使用资源库。保留来源、原作者、许可，避免重新分发未获授权的配方。

### E. Skill 生成历史与作品发布（P2）

Skill 每次任务保留稳定 run ID、原始用户创作指令的私有记录、输出图片与使用的画风/图型 ID 和版本；用户可选择将本次结果保存到网站个人私有历史。

生成结果的标准用户操作：
- 下载/查看图片
- 保存到个人云端（仅本人可见）
- 编辑并确认发布到网站作品广场

分享客户端复用既有 community-share 草稿与 /api/entries 对接思路。发布前必须显示将公开的标题、图片、说明、关联资源及提示词内容，避免将私有原始指令、系统提示、内部路径、商业秘密意外公开。

每次发布使用稳定 requestId；发生超时先查发布状态，避免重复作品。成功后显示真实作品链接。**不把论坛帖当作作品广场作品替代品。**

### F. 与网站互动（P3）

复用网站唯一作品/资源 ID，按鉴权范围调用服务端 API：
- 作品详情与本人发布记录
- 点赞、取消点赞
- 收藏、取消收藏
- 作品评论、回复
- 新评论与重要通知（先轮询，后续再评估推送）
- 从网站作品跳转复用画风/图型（必须先校验授权）

Skill 端仅维护必要的离线缓存和未发送操作队列；互动的最终计数与状态以服务器为准。

## 需要由网站仓库提供或明确的接口

现有可优先复用的能力：
- 设备授权：POST /api/auth/device、POST /api/auth/device/token、GET /api/auth/me
- 自建图库：GET /api/library/assets、PUT /api/library/assets/{uid}、DELETE、restore
- 已有个人资源/社区收藏适配入口：GET /api/skill/library 等
- 图片上传、作品创建：POST /api/uploads、POST /api/entries

待双方冻结正式契约后开发的新增接口（目前仅为规划）：
- GET/PUT /api/v1/me/resources：私有画风/图型双向同步
- GET /api/v1/me/collection-items：收藏与授权状态统一读取
- GET /api/v1/resources/{id}/download：授权完整资源读取
- POST/GET /api/v1/me/generations：Skill 私有历史导入与查询
- /api/v1/works/{id}/comments、likes 和 /api/v1/me/notifications：互动适配层

服务端所有内容返回应明确 ID、schemaVersion、revision、updatedAt、授权状态与分页游标。客户端所有写操作传 requestId，冲突保留用户数据，不以无限重试覆盖服务端版本。

## 分阶段交付与合并策略

| 阶段 | Skill 分支工作 | 验收 |
| --- | --- | --- |
| P0 身份基础 | 绑定设备、令牌安全存储、当前账号状态、错误反馈 | 身份与网站一致，网站撤销立即生效 |
| P1 资产同步 | 图库云端备份与恢复、个人画风/图型、完整收藏同步、画廊分区 | A 设备创建、B 设备恢复；未授权定义不可下载；离线不丢数据 |
| P2 作品闭环 | 生成记录导入私有历史、发布草稿与用户确认、幂等回执 | 没确认不公开；确认后网站恰有一条作品 |
| P3 互动 | 收藏、点赞、评论、通知和跨端状态刷新 | Skill 与网站同一状态，不产生第二套评论或计数 |

开发从当前 **feature/skill-web-unification-v1-20261107** 开始。每个阶段拆成小 PR，提交前检查本地官方资源未被改动、所有个人文件依然 gitignored、鉴权和离线失败路径有测试。网站 API 尚未实现时，不在 Skill 中通过未授权页面抓取或私有 Cookie 复制绕过权限；允许在测试中使用明确标注的假服务。

## 端到端验收清单

- [ ] Skill 绑定网站现有账号，能查看当前用户名并主动解绑。
- [ ] 本地创建角色/道具/场景后，网站本人图库可见，另一设备能恢复。
- [ ] 同一素材两端编辑不丢内容，409 冲突能保留副本。
- [ ] 新建画风/图型后网页本人可复用，访客不可见。
- [ ] 网站只收藏未解锁资源时 Skill 不获得完整定义；已授权可下载。
- [ ] Skill 生成图片后个人历史可见，但没有自动出现在公开作品广场。
- [ ] 用户确认发布后网站出现恰好一件作品，重复尝试不重复发布。
- [ ] 网站上的评论、点赞、收藏在 Skill 中可查询、可同步。
- [ ] 断网、令牌失效、无权限、服务器错误都不会造成用户本地数据丢失。

## 设计治理

这是一份实施基线而不是已完成功能清单。跨端数据模型、权限、默认私有规则、生成历史与作品关系调整，必须先更新网站仓库主文档，再更改客户端代码及测试。任何使个人历史自动公开的变更不属于本规划，必须单独进行用户意愿和历史数据迁移评审。

后续里程碑的实现状态、相关 PR、测试证据及行为变更，应回写本文件，避免新成员把规划内容误认成现有行为。
